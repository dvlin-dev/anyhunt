Anyhunt 1.0 已从固定 Digest 产品重建为 Topic 驱动的 Pi Agent 产品。Pi 是唯一 Agent Loop，
外部能力统一作为 Tool/MCP 暴露，研究经验保存为标准 Agent Skill。实现坚持 YAGNI：只保留当前
闭环需要的模型、运行时和运营面，不为假设中的未来需求预建平台、插件系统或兼容抽象。

## 2. 最终范围

### 产品闭环

```text
Topic → Pi 自主研究 → Evidence → RunItem → Inbox / Email / Webhook
           ↓
       Managed Skill

用户也可以导入 Attached Skills；Agent 在每轮运行中按需激活多个 Skill。
```

- Topic 是研究目标、调度和共享结果的唯一主体；公开 Topic 的关注者共享同一次 Run。
- Subscription 只表达用户关注关系、投递偏好与用户级调度覆盖。
- 首次和后续研究都由 Pi 自主选择 Tool/MCP；每条结果必须引用本轮 Evidence Ledger。
- 一个 Topic 最多有一个可自动演进的 Managed Skill，并可关联 0–20 个只读 Attached Skill。
- Run 支持手动/定时触发、流式执行、停止、失败、检查点恢复和幂等重试。
- 投递只包含 Inbox、Email 和签名 Webhook；1.0 不包含 Billing、Credits、Cloud Workflow 或 Connector SDK。

### 产品数据模型

产品闭环只有以下九个 Prisma 模型：

1. `Topic`：研究目标、公开级别、调度与最新运行状态。
2. `Subscription`：用户对 Topic 的关注、投递偏好和用户级设置。
3. `Skill`：标准 Skill 的身份、来源、所有权和当前版本。
4. `SkillVersion`：不可变的 `SKILL.md` 内容与版本历史。
5. `Run`：一次 Topic Agent 执行及其生命周期、检查点和统计。
6. `RunItem`：本轮交付的结构化结论与证据引用。
7. `UserItemState`：用户对共享结果的已读、保存和不感兴趣状态。
8. `Delivery`：Inbox 之外的 Email/Webhook 幂等投递记录。
9. `TopicReport`：公开 Topic 的举报与治理状态。

Topic 与 Attached Skill 使用 Prisma 隐式多对多关系，不增加领域 Join Model。认证、审计、请求日志、
幂等记录和加密 LLM 配置继续作为支撑模型存在；Inbox 是查询视图，不建立 Inbox 表。

### 模块边界

```text
apps/server/src/
├── agent/          # 运行合同、Pi Adapter、Runner、Skill、Tool/MCP、Evidence
├── topic/          # Topic、Run、RunItem、调度和 Owner 命令
├── subscription/   # 关注关系与投递偏好
├── inbox/          # 无表查询与 UserItemState
├── delivery/       # Email/Webhook 幂等投递
├── auth/ user/     # 身份与用户生命周期
├── admin/          # 最小运营与治理 API
├── llm/            # 加密 Provider 配置与 Pi Model 解析
└── search/ scraper/ browser/ map/ rss/ # Agent 内部采集能力
```

- `agent` 不拥有 Topic、Subscription 或 Delivery 实体，只执行一次 Run。
- `topic` 不实现 Provider、抓取或投递；`delivery` 不生成内容。
- Search/Scraper/Browser 只返回文本、链接与元数据，不承担对象存储或媒体处理。
- Web/Admin 使用函数式 API Client，不导入 Server 源码，也不接收 Provider 密钥。

真实 Provider 验收使用模型 `gpt-5.6-luna`，端点类型为 OpenAI-compatible proxy；最终 Smoke
耗时 88.0 秒并完成 14 次 Tool Call。记录不包含密钥、完整端点、Authorization Header、Prompt、
Skill 正文或采集正文。

真实页面验收确认：

- 两个隔离用户完成 Topic 创建、两轮研究、Managed Skill、两个 Attached Skill、发布、关注与用户状态。
- 关注者收到 2 条 Inbox 结果、1 封 Email 和 1 次签名 Webhook；外部 Delivery 均为 `DELIVERED`、
  `attempts=1`，Webhook Sink 只有一条匹配幂等键的请求。
- Owner 可在 Topic 和 Run 页面停止活动 Run；状态最终持久化为 `CANCELED`。
- 375×812 移动视口无横向溢出，首个键盘焦点为 Skip Link。
- Admin 可核对同一 Run 的 Provider、Tool、Skill、Delivery、Queue、Logs 与 MCP 状态。

验收发现并关闭的两个产品问题：

1. 活动 Run 缺少 Stop 入口：在 Topic 与 Run 详情补齐 Owner Stop，并增加单元与 E2E 回归。
2. Webhook 保存失败时表单静默关闭：保留表单并显示稳定英文错误；生产继续只允许 HTTPS，Docker
   验收只对一个完全相等的本地 Sink URL 开放显式例外。

## 6. 本地复验

```bash
pnpm install
cp .env.example .env
chmod 600 .env
# 填写 OPENAI_API_KEY、OPENAI_BASE_URL、OPENAI_MODEL
pnpm docker:up
pnpm docker:smoke
pnpm --filter @anyhunt/web test:e2e
pnpm --filter @anyhunt/admin test:e2e
```

完整静态、单元、集成与构建命令见根 `README.md`。`.env`、浏览器会话、截图、视频和验收报告均
保持本地忽略；Mock/Fake 只用于确定性测试和故障注入，不能替代真实 Provider 验收。
