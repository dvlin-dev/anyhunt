# Anyhunt 1.0 实施计划

> **给执行 Agent：** 必须使用 `executing-plans` 按任务执行，并用复选框持续更新进度、验证证据和未完成门禁。

**目标：** 将现有固定 Digest 产品收敛为可上线的 Topic 驱动 Pi Agent：Topic 共享 Run，用户通过 Subscription 关注，Agent 组合多个标准 Skill，并只自动维护一个 Topic Managed Skill。

**架构：** 保留现有 Web Reader、Admin、认证、LLM Provider、Search、Scraper、RSS、Map、Browser、Redis/BullMQ 与通知基础设施；重建精简的 Topic、Subscription、Skill、Run 和 Delivery 领域。删除固定 Search→Source→Scrape→Score 流水线、Edition/Content/Source/Feedback Pattern 重复模型，以及 Billing/Quota/Payment/Redemption 全部商业化代码。

**技术栈：** TypeScript、NestJS、BullMQ、PostgreSQL/Prisma、Redis、Pi (`@earendil-works/pi-agent-core` / `@earendil-works/pi-ai`)、MCP SDK、Zod、TanStack Start、React、Vitest、Testcontainers、Playwright。

---

## 0. 事实源与执行边界

- 产品范围：`docs/design/product-purpose.md`
- 领域与 Runtime：`docs/design/agent-and-skills.md`
- 当前固定流水线：`apps/server/src/digest/processors/subscription-run.processor.ts`
- 当前 Schema：`apps/server/prisma/main/schema.prisma`
- 当前 Web：`apps/web/src/features/digest/`、`apps/web/src/components/reader/`
- 当前 Provider：`apps/server/src/llm/`

### 保留

- User/Auth、Admin 权限、LLM Provider/Model 加密配置；
- Search、Scraper、RSS、Map、Browser 的真实采集实现和 SSRF Guard；
- PostgreSQL、Redis、BullMQ、Email/Webhook 基础设施；
- Web Reader、Explore、Topics、Subscriptions、Inbox 的界面体系；
- Admin 的 Topic、举报、运行、队列、Provider 与日志入口。

### 删除

- Billing、Quota、Payment、Credits、会员等级、Pricing 和 Redemption；
- 对外采集平台与按次计费合同，采集能力只作为 Anyhunt 内部 Tool；
- `DigestSource`、`DigestSubscriptionSource` 和 Source Refresh/Scheduler；
- numeric score、固定 AI Summary/Prompt、`DigestFeedbackPattern` 和 Learning Suggestions；
- `ContentItem`、`ContentItemEnrichment`、Edition 及其重复 Item；
- 旧 AI SDK Agent 调用、双读/双写、feature flag 和迁移脚本。

### 不新增

- Workflow、Connector、Strategy、Memory、通用 State、向量数据库；
- Skill Marketplace、用户脚本执行、用户任意 MCP、Shell 或 SQL 写入；
- 每位订阅者独立运行同一 Topic 的个性化执行模型。

## 1. 目标产品模型

核心闭环只有 8 个模型：

```text
Topic
Subscription
Skill
SkillVersion
Run
RunItem
UserItemState
Delivery
```

公开 UGC 额外保留 `TopicReport`。认证、LLM 配置、审计、请求日志和幂等记录属于支撑系统。

关键关系：

```text
Topic 1──* Run 1──* RunItem
Topic *──* Skill
Topic 0──1 managed Skill
User *──* Topic through Subscription
Skill 1──* SkillVersion
Run *──* Subscription through Delivery
User 1──* UserItemState keyed by canonicalUrlHash
```

    ├── email-delivery.processor.ts
    └── webhook-delivery.processor.ts

边界：

- `agent` 不拥有产品实体，只执行一次 Topic Run；
- `topic` 拥有研究目标、调度、Run 和 RunItem；
- `subscription` 只拥有关注关系与投递偏好；
- `inbox` 只查询，不建立 Inbox 表；
- `delivery` 只处理 Email/Webhook 幂等投递；
- 采集模块提供 Tool Adapter，不复制网络实现。
